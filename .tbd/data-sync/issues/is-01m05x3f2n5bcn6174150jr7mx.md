Linear's IssueCreateInput exposes createdAt and completedAt, self-described 'e.g. if importing from another system' — which is exactly what the mirror is. tbd sends neither, so Linear stamps both at sync time.

Live consequence of the three-repo onboarding: 53 issues 'created 2026-08-10' and 99 'completed 2026-08-10..16' regardless of real history (e.g. a bead with closed_at 2026-01-16 shows completedAt 2026-08-13). This breaks Linear's auto-archive (counts from completedAt, so old work occupies the active view and the issue quota for months), distorts insights/velocity, and misleads a human reading the issue.

Fix on the CREATE path only — Linear deliberately does not allow setting these on update, and in steady state a transition-stamped completedAt is near-honest because sync runs within minutes of the close. The distortion is an onboarding/backfill artifact, and onboarding goes through create.

Constraints from the schema: both must be in the past; completedAt must be after createdAt and requires a compatible (completed-type) workflow state — send it only when the bead's status maps to completed/canceled, and clamp completedAt to >= createdAt.

Touches: the outbound-create patch in sync-engine 7a and the mirror's create path, CanonicalPatch or a create-only input extension, adapter toInput, mock server honoring the fields.
