Config is committed and editable, so remapping must work or refuse loudly. Traced: today it splits silently (research §4.6, F17).

- policy change: SAFE — linked pairs keep syncing, mirror never shrinks, bulk guard gates widening.
- project change: new creates land in the new project; already-linked issues NEVER move (update path never sets projectId; ISSUES_BY_ID liveness fetch is unscoped, so they keep reconciling from the old project forever). Split-brain, silent.
- team_key change: old links keep reconciling, but every status push now sends the NEW team's workflow-state UUID against an OLD-team issue (toInput resolves stateId from configured team's ensureMeta, adapter.ts:667-669; Linear state ids are per-team) — a repeated per-item failure on every sync, forever. BROKEN.
- id_prefix change: the claim/idempotency URL embeds the display id (tbd://bead/<displayId>), so new syncs upsert under new URLs while old claims remain — every item accumulates a second tbd claim.
- Adjacent: resolveProjectId matches by name across the WHOLE workspace, first hit wins on a name collision.

Fix is visibility plus one guard, NOT migration tooling:
1. Sync report and tbd doctor flag linked issues whose team no longer matches team_key, once, with a count.
2. Never push a workflow-state id to an issue in a different team than the one it was resolved from; skip status for that pair and say why.
3. setup-linear documents: policy changes safe; project/team_key changes affect new creates only; moving existing items is a deliberate operation.
