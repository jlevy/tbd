Follow-up to tbd-0oz8 (fixed in #287). Verified by reading main @ 1238038e.

After #287, an incoming Beads issue whose short ID collides with an unrelated tbd issue is imported under a new ID. `tbd import --validate` still looks beads up by short ID (cli/commands/import.ts ~:347-354), so it compares the incoming bead against the unrelated native issue and reports false mismatches.

Fix: validate by recorded Beads source identity (the `existingByBeadsId` map the import path uses), with a test that imports a colliding short ID and then validates cleanly. Related open bead: tbd-gju9 (count before write; write failures warn only under --verbose).
