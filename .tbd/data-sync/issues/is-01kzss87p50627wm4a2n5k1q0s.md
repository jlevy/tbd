The one-second reconciler can call BoardState.reload while a standard tbd create/update/sync holds the shared data-sync lock and is mutating several files. A lock-existence check plus data metadata cannot prove safety when a complete writer begins and ends between checks. Define and implement a non-blocking seqlock-style writer fence in the central shared-lock wrapper: publish an active unique epoch before mutation and a quiescent epoch before release; accept only candidates bracketed by the identical quiescent epoch with the writer lock absent. Stage all files privately, reject incomplete or unstable candidates, and prove that no intermediate snapshot is externally visible.

## Notes

First-principles review refined the required mechanism on 2026-08-11: filesystem timestamps are reconciliation hints, not a transaction proof. The persistent writer epoch is the transaction fence; the metadata marker remains the missed-event trigger.
