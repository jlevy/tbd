Assignee needs a value, and every agent inventing its own string makes the field useless for grouping. Expose as 'tbd whoami'. Keep it non-person-identifying by default, consistent with the existing user_map stance.

Format decided (research-2026-08-14-agent-and-session-identity.md section 5.2): reuse tbd's internal ID tier with a different prefix.

- Canonical: `agid-{ulid}` — the same shape `generateInternalId()` already produces for `is-{ulid}` (ids.ts:104). 80 random bits, so it is safe to mint uncoordinated at session start with no registry consultation.
- Friendly: a slugified name joined onto the canonical ID through the record, not concatenated into it. Brief and renameable precisely because it carries no identity. Display shows the name alone when unambiguous, appending a short ULID slice when not.
- Storage: one file per agent at `.tbd/data-sync/agents/agid-{ulid}.yml`, following `issues/is-{ulid}.md` and `bridge/*/links/`. Not a flat union-merged map keyed by name — see tbd-ysz0 for what duplicate keys do to ids.yml today.

Implementation is mostly generalizing three constants: `INTERNAL_ID_PREFIX`, `INTERNAL_ID_PATTERN`, and `validateIssueId` (ids.ts:77-137) hardcode `is`, while `extractUlidFromInternalId`, `isShortId`, and the display-prefix grammar are already prefix-agnostic.

Two revisions to the earlier sketch on this bead:

- Resolution should start from hook stdin, not env. Codex sets no hook env vars at all, so an env-first design silently no-ops there. tbd's SessionStart script already receives the payload and discards it.
- `<agent-kind>@<host>` cannot distinguish two concurrent sessions on one host, and carries a hostname. It stays only as the degraded fallback when no harness identity is available.
