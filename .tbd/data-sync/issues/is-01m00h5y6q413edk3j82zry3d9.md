Assignee needs a value, and every agent inventing its own string makes the field useless for grouping. Resolve in order: --as <name>, $TBD_AGENT, then a derived default such as <agent-kind>@<host>. Expose as 'tbd whoami'. Keep it non-person-identifying by default, consistent with the existing user_map stance.

Research: research-2026-08-14-agent-sync-protocol-and-hooks.md E2

Deeper survey: research-2026-08-14-agent-and-session-identity.md (tbd-4rzn). It revises the sketch above on three points:

- The resolution order should start from hook stdin, not from env. Codex sets no hook env vars at all, so any env-first design silently no-ops there. tbd's SessionStart script already receives the payload and discards it.
- <agent-kind>@<host> cannot distinguish two concurrent sessions on one host, and carries a hostname. Prefer a minted id plus a separate mutable name.
- If an id is minted per session, it is minted uncoordinated across machines, so the bead short-id registry loop does not protect it. 9-10 base36 chars, not 4-6.
